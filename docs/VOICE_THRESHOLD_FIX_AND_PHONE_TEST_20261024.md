## Identified divergence

We compared the same pinned public audio and installed `mn6_en` model through the literal upstream `memcpy` frame loop and our portable PCM frame loop. The preceding failed comparison recorded 88 matching frame fingerprints and states, so transport/framing did not explain the common recognition failure. Registered commands, forward/reverse FST presence and the installed model pack were verified. Raw PCM is mono signed 16-bit little-endian, 16 kHz; model frames contain 512 samples. Complete uploaded sample counts and CRCs match. Reference-only AFE and other controlled experiments did not resolve the failure; their evidence is retained.

Pinned ESP-SR 1.7.0 commit `07b0a4d0f6b5de755874d5405150ee0a8eec9865` has a threshold-unit mismatch in the specific MN6 archive used here. Disassembly plus read-only target observations show that the public setter stores its probability argument directly at model offset 224, while `rnnt_path_is_qualified` compares mean **log probability** with that field. The result path returns `exp(mean_log_probability)`. Native default is -2.0; our old setter call wrote +0.7, equivalent to an impossible probability of 2.01375. The unchanged probability policy 0.7 must instead be represented as `ln(0.7) = -0.35667494` internally.

The narrow compatibility adapter invokes the vendor setter, verifies its exact raw-store behavior and writes the equivalent log value. It fails closed for invalid input or a different observed layout. CMake permits only the verified archive SHA256 `c5d8c65bee0467ad3620252c62d038364747e1a58344e6e070e9d10da8062e22`; any library update requires adapter review. This uses a private ABI and is deliberately pinned. Model weights/library files are unchanged. Firmware and Android still require returned probability >= 0.7. No confidence threshold was relaxed.

Official pinned comparison sources: [MultiNet reference test](https://raw.githubusercontent.com/espressif/esp-sr/07b0a4d0f6b5de755874d5405150ee0a8eec9865/test_apps/esp-sr/main/test_multinet.c), [recognition documentation](https://raw.githubusercontent.com/espressif/esp-sr/07b0a4d0f6b5de755874d5405150ee0a8eec9865/docs/en/speech_command_recognition/README.rst). The threshold defect is our analysis of the hash-verified binary and target observations, not a claim quoted from these documents.
